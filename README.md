# 💰 一起分帳 POC — 聚餐旅遊分帳計算器

一個**單一 HTML 檔案**的分帳工具雛型（Proof of Concept），解決聚餐、旅遊時「誰墊了多少錢、誰欠誰多少」對帳困難的問題。輸入品項與付款人後，自動算出每個人最後該付或該收多少，並把互相欠的錢**化簡成最少筆轉帳建議**。

## 🎯 問題痛點

| 項目 | 說明 |
|---|---|
| 使用對象 | 常和朋友聚餐、出遊，又常先幫大家墊錢的大學生 |
| 使用情境 | 多人聚餐或旅遊後，要整理每筆花費、誰有吃、誰該付多少 |
| 困難與影響 | 每人分攤的品項不同，手算容易算錯或漏收；互相欠來欠去（A 欠 B、B 欠 C、C 又欠 A）轉帳轉不完，催款也很尷尬 |

常見的困境：

- 同行的人各自墊了好幾筆消費（有人墊住宿、有人墊餐費）
- 帳目對到一半就亂了，或有人算錯多付少付
- 互相欠來欠去，轉帳轉不完

## 🔄 工作流：導入前後

### 導入前（全部由人工完成）

```
拍收據記品項 → 群組詢問誰吃什麼 → 手動計算每人金額 → 催款並對帳
   （人）           （人）              （人）             （人）
```

最容易卡住的地方：**手動計算每人金額**。每人分攤的品項不同，容易漏算、算錯，還要反覆確認。

### 導入後（本工具）

```
輸入花費與分攤者 → 自動計算每人金額 → 列出誰轉給誰 → 核對後傳給朋友
     （人）            （工具）           （工具）          （人）
```

### 🙋 Human in the Loop（人工確認的位置）

| 位置 | 由誰負責 | 說明 |
|---|---|---|
| 輸入花費與分攤者 | 人 | 品項、金額、誰付、誰分攤要由人輸入並確認正確 |
| 核對結果並回報 | 人 | 工具給的是「建議值」，人要檢查金額無誤後再傳給朋友、實際轉帳 |
| 計算與化簡轉帳 | 工具 | 自動計算每人淨額，並合併成最少筆轉帳建議 |

## 🤖 AI Agent 如何協助開發

本專案使用 **OpenCode**（於 VS Code 中操作）這個 AI Agent 協助開發，流程如下：

1. **釐清需求**：先請 AI Agent 針對「聚餐分帳」的需求提問，確認功能範圍後再動手設計。
2. **產生雛型**：由 AI Agent 產出單一檔案 `split-bill-poc.html`（HTML + CSS + 原生 JavaScript）。
3. **測試與修正**：我用假資料實際操作，針對計算結果與畫面不合理的地方，請 AI Agent 修改。
4. **加入加分功能**：再請 AI Agent 加入多人付款、三種分攤模式、localStorage 自動保存、複製結果、匯出圖片等功能。

## ✨ 功能總覽

### 核心記帳

| 功能 | 說明 |
|---|---|
| 👥 成員管理 | 新增、改名（點 ✎）、移除（✕）；移除時會同步從所有品項退出 |
| ➕ 品項輸入 | 名稱、金額、誰付錢、誰分攤；可隨時編輯／刪除 |
| 💳 多人付款 | 一筆品項可多人支付：預設「平均付」，可切換「個別金額」（例：A 付 800、B 付 400） |
| 🧮 三種分攤 | **平均**（每人相同）、**百分比**（總和需 100%）、**份數**（依權重比例） |

### 結算

| 功能 | 說明 |
|---|---|
| 📊 每人淨額 | 顯示每人的「已付／應分攤／淨額」，正數＝可收回，負數＝應補給別人 |
| 🔁 債務簡化 | 自動把多筆互相欠的錢合併成**最少筆轉帳建議**（例：4 人只列出 3 筆轉帳） |
| ⚠️ 無效資料防護 | 百分比非 100%、個別付款總額不符等，會標紅警告並排除在計算外，不會算錯總帳 |

### 加分功能

| 功能 | 說明 |
|---|---|
| 💾 自動保存 | 資料存於瀏覽器 localStorage，重新開啟不會消失 |
| ✨ 範例資料 | 內建「溫泉小旅行」4 人範例，涵蓋各種分攤模式，方便快速上手 |
| 📋 複製結果 | 一鍵複製純文字結算摘要，直接貼到群組 |
| 🖼 匯出圖片 | 產出結算摘要 PNG 下載 |
| 📱 響應式 | 手機優先排版（右下快捷鍵跳至結算），桌機為雙欄、結算面板固定側邊 |
| 🖨 列印 | 支援列印成紙本收據 |

### 資料隱私

🔒 所有資料僅保存在**本機瀏覽器的 localStorage**，不上傳伺服器、不傳送任何請求。

## 🚀 開始使用

1. 雙擊 `split-bill-poc.html`（或拖入瀏覽器視窗）開啟
2. 先在「參與成員」加入同行的人
3. 在「新增品項」輸入名稱與金額，勾選付款人與分攤成員，選好分攤模式後送出
4. 右側「結算摘要」即時更新，依「轉帳建議」轉帳即可兩兩結清
5. 需要回報時按「📋 複製結果」貼進群組，或「🖼 匯出圖片」

### 分攤模式怎麼選？

| 模式 | 適用情境 | 範例 |
|---|---|---|
| 平均 | 大家均攤 | 住宿 $4,800 由 4 人平分 → 每人 $1,200 |
| 百分比 | 有人吃得多／房間等級不同 | 早餐 $640 → 40% / 30% / 20% / 10% |
| 份數 | 依人數或權重（如雙人房 vs 單人房） | 油資 $1,200 → 2份 / 1份 / 1份 / 2份 |

## 🧮 計算邏輯

```
每人淨額 = 實際付款總額 − 應分攤總額
         = Σ（他是付款人的品項分攤額）− Σ（他參與分攤的金額 × 分攤比例）
```

**債務簡化**：計算出所有人的淨額後，用貪婪配對 — 每次把「最大債務人」對「最大債權人」結清一筆，直到淨額歸零。此法可保證轉帳筆數為最少至接近最少（一般情境少於 n−1 筆）。

**無效資料處理**：無效品項（百分比 ≠100%、付款加總 ≠ 品項金額、無付款人等）會顯示警告原因並**不計入**總帳，確保結算一致性。

## 🛠 技術

- 純 HTML + CSS + 原生 JavaScript，**零依賴、零框架、零外部請求**
- 資料結構（localStorage key：`split-bill-poc-v1`）：

```jsonc
{
  "members": [ { "id": "…", "name": "小明" } ],
  "items": [
    {
      "id": "…",
      "name": "溫泉會館住宿一晚",
      "amount": 4800,
      "payerCustom": false,
      "payers": [ { "mid": "…", "amount": null } ],   // null = 平均付
      "shares": { "mode": "percent", "list": [ { "mid": "…", "val": 40 } ] }
    }
  ]
}
```

- 金額一律顯示為 NT$（內部以小數運算，四捨五入到分，尾差進收款人身上以維持總額一致）

## ⚠️ 已知限制（POC 階段）

- 單一本帳、一次活動
- 資料僅在同一裝置／同一瀏覽器保存，跨裝置需重輸或匯出
- 除「匯出 PNG／純文字」外無其他匯入匯出格式（CSV、Excel）
- 結算為建議值，不含實際轉帳功能，需由人核對後自行轉帳
